# Job Watcher 설계 문서

- 작성일: 2026-07-27
- 목적: 여러 채용 사이트를 매일 직접 돌아다니며 확인하는 반복 작업을 자동화한다. 조건에 맞는 채용 공고만 걸러 로컬 대시보드 하나로 모아 보여준다.

## 배경 / 사용자 컨텍스트

사용자는 현재 구직 중이며(IT/전산/전산보안 직무, 광주 지역, 신입~2년차 경력 대상), 사람인·워크넷·잡코리아·잡다 등 여러 사이트를 매일 개별적으로 확인하고 있다. 이 확인 과정을 자동화하고, 결과는 알림 채널이 아닌 로컬 파일/대시보드로 받아 본인이 필요할 때 열어본다.

## 범위

**포함:**
- 사람인, 워크넷(고용노동부), 잡코리아, 잡다 4개 사이트에서 채용 공고 수집
- 사용자가 정의한 조건(직무 키워드, 지역, 경력 상한, 제외 키워드)으로 필터링
- 필터 조건은 설정 파일로 관리하여 사용자가 자유롭게 추가/삭제 가능
- 신규 공고와 기존에 본 공고를 구분 표시
- 하나의 로컬 HTML 대시보드로 결과 출력
- Windows 작업 스케줄러를 통한 매일 자동 실행

**제외 (YAGNI):**
- 알림 채널 연동(텔레그램/이메일 등) — 사용자가 로컬 파일 확인을 선택함
- 필터 조건을 위한 별도 GUI/CLI 편집 도구 — JSON 직접 편집으로 충분
- 지원 현황 관리, 자소서 자동 작성 등 구직 활동의 다른 영역
- 이력서 자동 지원(원클릭 지원) 기능 — 정보 확인 자동화만 요청됨

## 아키텍처

단일 Python 프로젝트로 구성한다.

```
job_watcher/
  config/
    filters.json          # 필터 조건 (사용자가 직접 추가/삭제)
  sources/
    base.py                # 공통 인터페이스 (JobPosting 데이터클래스, fetch() 시그니처)
    saramin.py              # 사람인 Open API 연동
    worknet.py              # 워크넷(공공데이터포털) API 연동
    jobkorea.py             # 잡코리아 스크래핑
    jobda.py                # 잡다 스크래핑
  filter.py                # filters.json 조건으로 매칭
  state.py                 # 이전 실행 기록 로드/저장, 신규 여부 판정
  dashboard.py              # HTML 렌더링
  main.py                   # 파이프라인 실행 엔트리포인트
  state.json                 # 실행 시 자동 생성/갱신 (이전에 본 공고 ID 목록)
dashboard.html               # 최종 산출물, 매일 덮어쓰기
```

각 `sources/*.py` 모듈은 `fetch(filters: dict) -> list[JobPosting]` 형태의 공통 인터페이스를 따른다. `JobPosting`은 제목, 회사명, 지역, 경력 조건, 링크, 마감일, 출처 사이트를 담는 단순 데이터클래스다.

## 데이터 흐름

1. `main.py` 실행 → `sources/` 하위 4개 모듈이 각각 공고를 수집한다.
   - 사람인: Open API 사용
   - 워크넷: 공공데이터포털 채용정보 API 사용
   - 잡코리아, 잡다: 공식 API가 없으므로 HTML 스크래핑, 요청 간 딜레이 적용
2. 모든 결과를 공통 `JobPosting` 형태로 정규화한다.
3. `filter.py`가 `config/filters.json`의 조건(직무 키워드 포함, 지역 포함, 경력 상한 이하, 제외 키워드 미포함)으로 필터링한다.
4. `state.py`가 `state.json`에 저장된 이전 공고 ID 목록과 대조하여 신규 공고에 `is_new=True`를 표시하고, 마감된 공고는 목록에서 제거한다.
5. `dashboard.py`가 필터링된 공고 목록을 하나의 `dashboard.html`로 렌더링한다(신규 공고는 상단/강조 표시, 사이트별 수집 실패 시 상단에 경고 배너 표시).
6. `state.json`을 이번 실행 결과로 갱신한다.

## 필터 설정

`config/filters.json` 예시:

```json
{
  "job_keywords": ["전산", "IT", "전산보안", "정보보안"],
  "regions": ["광주"],
  "experience_max_years": 2,
  "exclude_keywords": ["인턴", "파견"]
}
```

- `job_keywords`: 공고 제목/직무에 하나 이상 포함되어야 매칭
- `regions`: 근무지에 하나 이상 포함되어야 매칭
- `experience_max_years`: 요구 경력이 이 값 이하(신입 포함)인 공고만 매칭
- `exclude_keywords`: 제목에 포함되면 무조건 제외

사용자가 조건을 추가하거나 빼고 싶으면 각 배열에 문자열을 추가/삭제하면 된다. 별도의 편집 UI나 CLI 명령은 만들지 않는다 — 텍스트 편집기로 직접 수정하는 것으로 충분하다.

## 에러 처리

- 특정 사이트 수집이 실패해도(네트워크 오류, 사이트 구조 변경 등) 전체 파이프라인은 중단되지 않고 나머지 사이트 결과로 계속 진행한다.
- 실패한 사이트는 대시보드 상단에 "○○ 수집 실패" 경고 배너로 표시한다.
- 스크래핑 대상(잡코리아, 잡다)은 요청 사이에 짧은 딜레이를 두어 과도한 요청을 피한다.

## 스케줄링

Windows 작업 스케줄러에 매일 정해진 시각(예: 오전 9시)에 `python main.py`를 실행하도록 등록한다. 결과는 `dashboard.html`에 덮어쓰기 되므로 사용자는 필요할 때 이 파일을 열어 확인한다.

## 테스트

- 각 `sources/*.py` 모듈은 저장해둔 샘플 응답(fixture)을 사용해 파싱 로직을 단위 테스트한다(실제 네트워크 호출 없이).
- `filter.py`는 샘플 `JobPosting` 리스트와 다양한 `filters.json` 조합으로 매칭 로직을 단위 테스트한다.
- `state.py`는 이전 상태와 새 수집 결과를 비교했을 때 신규/마감 판정이 올바른지 단위 테스트한다.
